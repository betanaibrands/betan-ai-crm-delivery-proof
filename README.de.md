# Einfach erklärt: Was diese Arbeitsprobe zeigt

Stell dir vor, eine Agentur verkauft ein Projekt. Die Daten liegen danach im
CRM, aber Delivery braucht daraus ein korrekt angelegtes Projekt, einen Ordner
und einen eindeutig sichtbaren Übergabestatus.

Eine einfache Verbindung kopiert nur Daten. Diese Arbeitsprobe prüft zusätzlich:

- Sind alle nötigen Angaben vorhanden?
- Hat ein Mensch die Übergabe freigegeben?
- Wird bei einem zweiten Lauf kein Duplikat erzeugt?
- Bleibt bei einem Fehler kein unklarer halbfertiger Zustand zurück?
- Kann ein anderer Mitarbeiter anhand von Tests verstehen, was passieren muss?

## Mein Satz für ein Gespräch

> Ich verkaufe nicht bloß eine Verbindung zwischen zwei Programmen. Ich baue
> einen abgegrenzten Übergabeprozess, der Pflichtfelder und Freigaben prüft,
> Duplikate vor dem Schreiben stoppt, Fehler sichtbar macht und anhand
> schriftlicher Fälle abgenommen werden kann.

## Was wirklich bewiesen ist

Der Workflow verarbeitet 20 vollständig fiktive Testfälle. Diese Fälle laufen
reproduzierbar und ohne externe Aufrufe. Erfolgs-, Fehler-, Duplikat- und
Rollback-Wege werden maschinell geprüft.

## Was nicht behauptet wird

- kein Kundenprojekt;
- keine Live- oder Produktionsumgebung;
- keine echten Kundendaten;
- keine allgemeine Produktionsreife;
- keine gemessene Umsatz- oder Zeitersparnis bei einem Kunden.

Für einen echten Auftrag würden Trigger, Systeme, Felder, Testzugänge und
Abnahme zuerst schriftlich festgelegt. Erst danach folgen Festpreis und Termin.
